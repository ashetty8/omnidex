  `assets/habitat-icons/`.
- **Color**: every species has `colors: string[]` (was PokeAPI's single-value

## Gotchas hit this session (avoid repeating)

- **`JSON.stringify(obj, arrayOfKeys, indent)`** — passing an array as the
  replacer filters keys **recursively at every nesting level**, not just the
  top level. Used `Object.keys(map).sort()` as a replacer to get sorted
  output and it silently reduced every nested `{colors, habitats}` object to
  `{}` (arrays were unaffected, since array indices aren't string keys, which
  is why `colors.json`/`habitats.json` were fine but `form-overrides.json`
  came out empty until caught by a smoke test). Just don't use a replacer
  array when values are objects — sort via `Object.fromEntries` instead.
- **pokedle.com's `/api/infinite-games/{mode}/start` does NOT return a fresh
  session per call** — it's a persistent session tied to the browser
  identity that accumulates every guess ever submitted. Calling `start`
  repeatedly just returns the same session with its growing `guesses` array.
- Rapid sequential guess submissions raced with backend consistency and
  silently returned **stale/wrong data for ~15% of a 1025-item sweep** (not
  obviously broken — looked like plausible but wrong colors). Always verify
  by checking the echoed `pokemonNumber` on each guess result matches what
  was requested before trusting the value.
- Reliable pattern that worked: submit all guesses into one persistent
  Infinite-mode session (start a **new** session via `start` whenever
  `isWon` flips true, since a won session stops returning fresh guesses),
  then re-call `start` once at the end to fetch the complete session state
  and extract each result by `pokemonNumber` from the full `guesses` array —
  far more reliable than trusting `guesses[guesses.length - 1]` per request.
- Copying long base64 strings by hand (e.g. reproducing icon data from a
  tool result into a `Write` call) is genuinely unreliable — silently
  corrupted ~10 of 22 icon files on the first pass. Fix: chunk into ~200-char
  pieces, have the browser compute a SHA-256 (or even an 8-char slice of one)
  per chunk, and verify each chunk's hash after transcribing before trusting
  the assembled file.
- `javascript_tool` browser calls time out at 30s — keep sequential-fetch
  batches to ~50–65 items per call when hitting an external API.
- **Trust the actual artwork over recalled/written descriptions.** The
  previous handoff's claim "Meowstic female is purple" turned out to be
  wrong once the real sprite was viewed — she's blue+white like the male.
  Always download and view the sprite before writing a color override; don't
  rely on memory of what a Pokémon "looks like."
- **The app has a deliberate "anti-search" feature** (`app.js`,
  `findExactPokemonMatch`/`applyPokemonSearchFilters`): typing a Pokémon's
  *exact* name into the search box doesn't text-filter — it resolves to the
  negation of that Pokémon's own type/gen/habitat/evolution-stage attributes,
  surfacing "Pokémon unlike this one." Looks like a stuck/buggy filter state
  if you don't know it's intentional. Use a non-exact query (e.g. add a
  second word) or click into cards directly when you just want to find one
  specific Pokémon while testing.
